# Agent Note: 浏览器会话通知

Status: implemented

[English](2026-11-19-client-session-notifications.md) | 中文

## Problem

当会话开始等待用户输入，或在用户不看页面时结束，此前只能从页面内部察觉：侧栏行的状态变了，操作系统毫无感知。用户在别的应用里工作时，要切回来才知道有等待或失败。

这些事实在客户端已经存在。`ctx.uiSession.sessionStatus` 为每个会话发布运行状态、生效的待交互请求与阅读提醒，宿主 Remote 服务在重连之间保存这些提醒。

## Decision

新增客户端插件 `@deepseek-ai/dsh-client-ui-session-notifications`，把状态迁移转成浏览器或操作系统通知。它不持有宿主状态，也不渲染元素。

### 迁移规则

| 规则 | 理由 |
|---|---|
| 激活后的第一张状态表只是基线 | 启用插件不应补报页面打开时就已等待的会话；那是侧栏的现状，不是新事件 |
| 待交互请求在其 `key` 变化时通知 | key 标识交互本身，因此页面聚焦期间被另一个交互替换时仍会通知 |
| 完成在 `completionUnread` 变为 true 时通知 | 阅读提醒已经判断结束的回合是否值得报告，插件不重复这套判断 |
| 同一快照里待交互优先于完成 | 会话此刻在等用户，比刚刚结束的回合更值得提醒 |
| 离开状态表的会话丢弃游标 | 被删除或过滤掉的会话不能压住之后同一标识的等待 |

### 抑制

页面在窗口可见且聚焦时抑制通知，因为侧栏已把同样的状态显示在屏幕上。窗口可见但未聚焦、以及后台标签页仍然通知。`notifyPendingInteraction`、`notifyCompletion`、`notifyOnlyWhenUnfocused` 是宿主 `Config` 的 volatile 字段，因此 `cordis.yml` 的改动无需重挂插件即可到达已打开的页面。

### 权限

插件在第一次需要发送通知时申请通知权限，申请获准后立即补发这条触发申请的通知；弹窗未决期间后续产生的通知直接丢弃，因此权限弹窗不会打断回合开始，也不会堆积过期事实。权限被拒绝后，本轮页面内插件保持静默；运行环境没有 `Notification` 构造函数时同样静默，而不是退化成页面内横幅——侧栏已经提供了那层信息。

## Alternatives considered

| 方案 | 否决理由 |
|---|---|
| 在 `packages/experimental/hooks-claude-code` 增加 `Notification` 钩子事件 | 钩子协议在宿主上按会话事件执行一条 shell 命令，无法打开通知所指的会话；且只覆盖回合结束，不覆盖待交互请求 |
| 在 `apps/desktop/src` 做仅桌面端的 Electron 通知 | 桌面渲染进程已通过 Chromium 获得浏览器 `Notification` API，在 Electron 侧实现会把每个判断复制一遍，并让 Web 客户端保持静默 |

## Consequences

- 插件只依据客户端状态表通知，因此宿主在没有打开页面时不会发出任何通知。未来的宿主侧通知器会扩展这一决定，而不是取代它。
- 通知沿用侧栏的聚焦规则：用户正在阅读的会话不会被置为未读，因此读完一个回合不会产生通知。
- 迁移规则是对投影后状态事实的纯函数，无需浏览器即可测试；插件测试用脚本化的状态表、权限状态与聚焦状态覆盖。
