# Agent Note：账号菜单用量摘要

Status: implemented

[English](2026-10-18-account-menu-usage-summary.md) | 中文

## Problem

侧边栏账号菜单回答“当前登录的是谁”并提供退出登录，但已登录用户最常查看的充值余额和当天消费金额只存在于 Platform 用量页面。打开该页面会离开 GUI，而其时间筛选和导出控件对快速查看账号状态并不必要。

## Decision

账号能力新增 `getUsage(client)`，由 `AccountController` 暴露为 `account/getUsage`。一次 Host 调用读取 Platform 的 `usage/by_api_key/cost` 接口。时间窗覆盖调用方当前本地日，由 `AccountClientMetadata.timezoneOffsetSeconds` 的完整偏移计算得出；查询以该偏移的整小时形式作为 `tz`，即 Platform 用量页使用的分桶时区。Host 按币种汇总金额时同时累加模型的 `series` 与工具调用的 `function_series`。Host 读取 API Key 列表，选择最新的 DeepSeek Harness（`DSH`）Key，并按它的 tracking id 过滤查询，使菜单与从 Harness 打开的用量页面一致，而不是叠加其他 Key 的流量；账号没有 DSH Key 时查询不添加筛选。用量失败不产生部分合计；额度行继续使用共享账号资料快照中的充值余额，该快照在登录和每次进入设置时刷新。

已登录的 `AccountMenu` 通过新增的非交互 `Menu.header` 属性把用量区域固定在操作项上方。每次打开都发起一次新的读取：在结果绘制前把头部重置为“加载中…”，绝不显示上一次打开的合计，失败时显示“暂不可用”且不隐藏菜单操作。由于固定头部位于菜单的行键盘走位之外，启动按钮同时把同一组合计作为可访问描述暴露，辅助技术无需进入菜单模式即可读取。金额复用现有余额格式化；Platform 未返回金额行时使用账号钱包币种，没有已知钱包币种时显示不带符号的零。两行下方有一条进度条，按当天消费占第一个钱包余额的比例填充：50% 以内使用成功色，80% 以内使用警告色，超过 80% 使用错误色，按显示的百分比判定，使颜色与朗读值一致；没有匹配的钱包或金额时不显示。不提供时间筛选或导出。关闭菜单会丢弃仍在进行的读取，退出登录会清除保留的结果。固定 UTC 偏移无法表达夏令时切换日，因此 23 或 25 小时的本地日按 24 小时窗口查询。

## Alternatives considered

**复用内嵌 Platform 用量页面。** 它已经渲染这四个数字，但必须离开菜单；本次变更的目标是“一眼可见”。**拒绝**作为唯一入口。

**从本地 Session token 用量推导。** DSH 已记录 token 用量，但这些记录只描述本安装的 Session，而不是跨 API Key、工具和其他客户端的整个 Platform 账号。**拒绝**，因为量纲不同。

**返回原始用量序列并在浏览器聚合。** 这会把按 Key、模型和时间桶的行推过 Remote，并在客户端重复 Platform 的折叠逻辑。Host 已持有凭据，可以一次求和。**拒绝**。

**增加用量页面的时间筛选和导出。** 两者都需要在只显示四个合计值的弹出菜单中加入额外状态、文案和布局；Platform 页面仍是完整工具。**拒绝**，视为超出范围。

## Consequences

打开已登录菜单会发起一次 Host 用量读取，其背后是两次 Platform 请求（API Key 列表和 cost 查询），因此菜单自身有了加载和失败状态。不同次打开之间不缓存合计，已关闭或被取代的读取不能更新头部。关闭菜单不会取消 Host 请求：Remote 调用不携带取消信号，Platform 读取会完成，只是结果被丢弃。账号服务、Remote 类型、生成的 Cordis 目录以及 primitive 的 `header` 公开面需一同更新。用量不可用时菜单仍可使用，账号 token 从不进入渲染进程。

## Testing

`usage.spec.ts` 固定整小时、带分钟和负偏移的时间窗（含本地午夜）、DSH Key 选择及其无 DSH Key 回退、多币种与零行金额、big.js 指数边界的十进制归一化，以及格式错误载荷。提供者测试覆盖成功读取的查询参数与客户端身份请求头、超过账号资料大小上限的用量报告、API Key 列表读取失败、HTTP 401 与业务码 40003 两种凭据拒绝、API Key 与 cost 载荷格式错误、未登录读取、读取期间凭据替换，以及迟到的拒绝不得清除替换后的凭据。Controller 测试固定委托关系。账号 UI 测试覆盖金额格式化、用量进度条及其取整阈值、每次打开（含第二次打开）的加载态、不可用、使用钱包币种的零消费、没有钱包币种时的不带符号零、启动按钮的可访问描述，以及菜单关闭后才结算的读取；primitives 测试固定 `header` 位于行键盘走位之外。聚焦覆盖率保持每个源文件 100%。
