# Agent Note: 工作区 git 视图与共享对比渲染器

Status: implemented

[English](2026-10-17-files-workbench-git-view.md) | 中文

## 问题

文件工作台能浏览和阅读工作区，却看不到读者自己改了什么。要看工作区状态就得离开 GUI 去终端，而产品里唯一的变更界面是按轮次的变更评审 —— 它回答的是"这一轮改了什么"，而不是仓库当前的状态。那个评审还独占了唯一带行号、带语法高亮的对比渲染器，且长在它自己的功能包里：按客户端的规则，另一个功能不能 import 它，而同包的另一个渲染器 `DiffBlock`（单列、只吃前后文本对）是兄弟包唯一能拿到的渲染器。

## 决策

工作台的活动栏提供第二个视图容器：当会话目录位于 git 工作树内时，`git.status` 报 `repository`，活动栏在文件项旁多出一个分支项。git 容器用变更视图替换两栏 —— 引导侧是选中路径与 `HEAD` 的对比，尾随侧按 Changes / Untracked Files 分组列出改动路径，两者之间是同一个可拖拽的 `SplitView`，对比区上方是两个纯图标开关，一个切换单栏或左右布局，一个切换整个文件或改动部分（默认改动部分）。每组可从标题折叠、默认展开；每行按类型给状态字母与文件名上色；对比、列表滚动位置、两个开关与比例都按 tab 记住。

Host 侧只有一份能力，不是第二套 git 栈：`workspaceChanges` 新增 `workingTree` 与 `workingDiff`。`workingTree` 通过轮次记录器已经约束好的运行器执行 `git rev-parse --is-inside-work-tree` 与 `git status --porcelain=v1 --branch -z --untracked-files=all`；`workingDiff` 把某路径的 `HEAD` 文本与工作副本并列，交给与轮次摘要相同的 `compareText`。工作台的 Host 半在连接鉴权栅栏内注册 `/api/git.status` 与 `/api/git.diff`：两者都解析会话并拒绝与会话实际解析出的工作目录不一致的请求，对比路由还拒绝逃出该目录的路径。这使得 `ui-sidebar-files` 成为双面包（Host 与 Client 各一个编译面），因为要提供路由的功能必须两面都在。

评审的带行号对比渲染下沉到 `ui-primitives`，名为 `DiffHunks`，评审页的 `FileDiff` 与 git 视图都经它绘制。`DiffHunks` 负责行号、hunk 配对、高亮、渲染行数上限以及单列/并排两种布局；`FileDiff` 只保留加载、不可用、二进制与重试这些状态。git 视图传入 `splitOneSided`，因此即使是纯新增或纯删除的对比，选择了并排也会照常并排绘制，没有内容的一侧留空；评审页则保持它自己对这类对比的单列默认。

## Alternatives considered

**独立成一个 git 插件包。** 最符合"一个 UI 功能一个包"的读法，但 git 视图**就是**这个工作台的一个容器，独立成包需要先设计活动栏的 slot 扩展点（项 + 容器渲染），而现在并没有第二个消费者。**否决**：改动面更大。

**从 git 视图直接 import 评审页的 `FileDiff`。** 能复用渲染器而不搬家，但客户端规则禁止功能插件运行时导入另一个功能插件的值；合法的跨界只有服务与 slot，而渲染器吃对比数据，两者都不合适。**否决** —— 所以是渲染器下沉，而不是导入。

**在工作台里再写一个并排渲染器。** 写起来便宜、隔离，但会成为产品里的第三个 diff 渲染器，并逐渐与评审页的排版、行号槽、高亮漂移。**否决**：一个渲染器，两种布局。

**在浏览器里计算对比。** 客户端没有命令执行能力，在浏览器里解析 `.git/index` 或对象文件也不值得拥有。**否决**。

**用轮次变更评审充当 git 视图。** 评审回答"这一轮改了什么"，不是"现在有什么未提交的改动"，而且它只在会话摘要存活期间存在。**否决**：不是同一个产品问题。

## Consequences

活动栏的容器列表现在是数据（tab 存储里的 `container`），第三个视图容器只扩展数组与 store，不改布局。对比引擎与渲染器各自只有一个归属，git 视图免费继承评审页的排版、行号槽、高亮与渲染行数上限。代价是一个双面包、一份在轮次记录器之外持有 git 事实的 Host 能力，以及两条鉴权路由而不是 Typert remote —— 因为对比载荷是视图状态，不是会话传输状态。视图是只读的：暂存、提交、切换分支与按文件打开原生应用都未实现。附带影响：`ui-open-in-app` 的项目引用改指工作台的 client leaf，生成的 API 目录记录了 `DiffHunks` 的新导出。

## Testing

单元覆盖：`workspace-changes` 解析状态记录（分支头、已暂存/未暂存两臂、重命名、未出生与游离 HEAD、被忽略记录），并在真实仓库上比较修改、新增、删除、二进制、超限与越界路径；`ui-sidebar-files` 覆盖路由契约的校验与坐标、处理的 400/404/409 及其会话、工作目录、路径检查、store 的 git 切片（状态、选择、对比、布局、比例、折叠分组）、面板的分组、布局控件、对比状态与按类型着色行，以及正文的探测、选择、记录结束后丢弃、切换与分隔条拖拽；`ui-primitives` 渲染两种布局、单边策略、提示、渲染行数上限与折叠标签。浏览器覆盖：工作台自己的用例在真实仓库上打开 git 容器、切换布局、折叠分组并记录行类型，绘制对比的 replay 场景继续经共享渲染器通过。
