# Agent Note: 后台会话的审批由侧栏条与框架队列作答

Status: implemented

[English](2026-11-19-sidebar-approval-answer-surfaces.md) | 中文

## 问题

审批请求属于发起它的会话，按钮因此长在该会话的 composer 里。同时开着多个会话时，后台会话的请求只能切换过去才够得着。侧栏已经有一个待处理圆点，它说明有事在等，却不说等的是什么 —— 而做决定仍然意味着离开正在读的会话。

这里需要两个surface。一个不切换即可作答，另一个在用户想一次处理多条时清空队列。两者都不允许不受限的主机授权一键完成，因为悬浮卡恰恰是容易误点的地方。

## 决策

两个surface都读 `ctx.uiSession.pendingInteractions`，并通过 `PendingApproval.answer` 结算。它们不新增会话事件、不新增 store、不新增 Host 接口：请求的 `reason` 已经携带了紧凑surface需要的结构。

负载是请求本身唯一不携带的事实。它存在发起会话的 `tool/call` 事件里，但客户端 Conversation 只为被某个引用 retain 的会话组装，因此读组装好的 Tool 调用节点只对屏幕上那一个会话有效。于是 `ApprovalService` 把会话正在询问的那些调用的参数折进 `approvalPayload` 会话投影，随会话列表行下发。两个界面都读这个投影，后台会话无需打开即可展示负载，客户端也不必为了一行命令去组装整段对话。

`approvalFacts` 把一个请求归约成动作行、模式与危险档位。对 sandbox 层来说审计原因是 `escalate sandbox to <mode>: <justification>`，于是 justification 成为动作句，模式指出正在被审的权限；其它发起方只提供散文，其提示词原样成为动作行。`danger` 是一个封闭集合的成员判断，当前集合只有 `danger-full-access`。

`ApprovalPeek` 注册进 `sidebar.session.row.hover` —— 会话行本来就在悬浮卡打开期间挂载它。审批行向 `HoverCard` 要一张更宽的卡片，于是卡内能同时容纳标题行、动作、权限、负载展开与两个决定，而不必把动作折成五行。卡内重复发起方与其权限模式，显示动作，展开这次请求要执行的负载，并给出拒绝、允许，以及打开发起会话的入口。危险请求把允许变成条内第二步：按钮先说出模式，确认行再次状述该模式，只有确认行会结算。`ApprovalInbox` 注册进 `shell.overlay`：计数胶囊在遮罩之上展开一个右缘抽屉，列出所有会话待处理审批，逐行决定同样遵守两步规则。批量拒绝永远可用；只要队列里有危险请求，批量允许即禁用，因为批量路径不该给出单行需要问第二次的东西。

两个surface的第二步状态都由待处理快照派生而非同步：`confirming` 由 armed 键与当前行计算得出，行消失时它的确认态一并消失，也没有 effect 把状态写回。

## 备选方案

**把按钮直接放进侧栏行。** 不需要悬浮卡、不需要延迟，但一行只有 28px，装着标题、状态和时长，而会话列表同时是导航面。把破坏性按钮摆在导航目标旁边，正是本决策要避开的误点。

**把命令、diff 与路径直接铺进 244px 卡片。** 为容纳它们生长的卡片在那个宽度下不再可读，而行的标题、路径、时长已经占满卡片前三行。卡片保留这三行，另加一句动作，把负载放到固定高度、内部滚动的展开区之后。

**所有请求都一键作答，包括 `danger-full-access`。** `.agents/notes` 记录悬浮卡是易误点的面；在那里一键，等于让最不可逆的授权变成最廉价的授权。

**两个注册共享一个 store。** 条与队列互不需要对方的状态 —— 各自从待处理快照派生 —— 所以 store 只会多出一个模块级 handle 和一处生命周期耦合。

**让客户端接缝向 Conversation 包要这次调用。** `ctx.approvalDetail` 让 `ui-chat` 注册一个读组装后 Tool 调用节点的解析器，`ui-approval` 因此不依赖 Conversation 包。代价是负载必须等发起会话被打开、Conversation 被保留之后才出现——而悬浮卡存在的意义正是免去那次导航。

**Host 侧队列接口。** 待处理 map 已持有全部会话的实时请求，结算路径也已存在。第二条路径需要自己的鉴权、缓存与失效逻辑。

## 影响

非 sandbox 发起方的请求会把整段本地化提示词作为动作行，可能是好几句。条内把动作裁到三行，队列同样裁剪，完整提示词仍在该会话的 composer 卡里。

加宽卡片是 `HoverCard` 的一个选项，而不是插件覆盖样式表：定位、边缘回退与紧凑宽度都由 primitive 拥有，想要别的宽度的调用方把它说出来。其余行仍用列表列宽。

危险档位是 `approval-facts.ts` 里的封闭集合。将来出现同样授予不受限访问的模式必须加入其中，否则它的请求会被一键放行。

`pendingInteractions` 在 Client 侧是先过滤再映射：surface收到所有域的待处理交互并只保留 `PendingApproval` 实例，因此正在显示提问的会话对两个计数都不贡献。

队列按会话 map 的迭代顺序排列而非请求时间，因为待处理 map 不携带时间戳。要加时间意味着新增 Host 字段，而不是在 Client 排序。
