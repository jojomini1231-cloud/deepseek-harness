# Agent Note: 文件工作台的 Git 历史视图

Status: implemented

[English](2026-10-19-files-workbench-git-history.md) | 中文

## 问题

文件工作台显示的是工作区，而不是仓库历史：读者能看到相对 `HEAD` 的未提交改动，却看不到更早的提交、引用，以及某个提交改了什么。最直接的外部参照 —— 桌面 Git 客户端 —— 用三栏：引用树、提交图，以及选中提交的改动文件与补丁。这放不进右侧栏：右栏从 300px 到视口约 70%，已经消耗了 48px 活动栏和两栏可拖拽的工作台导航与内容。硬做三栏的话每栏只剩 100–150px，diff 会被压到不可读；产品也没有第二个更宽的窗口可以承载这个视图，而读历史的人仍然需要把对话放在旁边。

## 决策

工作台的活动栏在 `files` 与 `git` 之外提供第三个视图容器 `history`，出现条件与 git 视图相同（工作目录是仓库）。这个视图复用工作台已有的两栏语法，而不是再加一栏：提交页在引导侧，历史导航在尾随侧，二者之间还是那个可拖拽的 `SplitView`，比例按 tab 单独保存。当实测的历史面板宽于 560px 时是两栏；窄于该值时变成单栏 —— 要么显示导航列表，要么显示选中提交的页面并带返回控件。宽度由 `ResizeObserver` 量视图自身而不是窗口，因为右侧栏可拖拽，同一个窗口里两种布局都会出现。

参照布局的三层被折成两层。引用变成筛选而不是一栏：导航头部放一个 chip，弹层里按本地分支、远程、标签分组并带搜索框，另有走 `HEAD` 的「全部引用」一项。选一个引用只重启当前列表，绝不切换分支。提交行从 refs 尖端生成引用标签，顺序优先当前分支，再本地、远程、标签。改动文件折进提交页，因此只有提交列表和选中提交的内容需要并排。

行首窄槽里画的是提交图，而不是一栏：`layoutGraph`（`history-graph.ts`）是对已加载提交（从新到旧）的纯车道布局，每行画出穿过该行的车道线段、自己的提交圆点，以及当前显示提交圆点外的一圈圆环。行本身就是层：git 的拓扑顺序让每个提交占一行，因此只剩车道的顺序与坐标。每个子提交都留一条车道等待自己的父提交，因此多条车道可以等待同一个提交；到该提交所在的行，这些车道在它的圆点处汇合：最左的等待车道成为圆点，其余车道从行顶斜向进入圆点，因此分支的线一直画到它分出的那个提交的圆点。每条车道在它等待的提交到达之前保持自己的列，因此除分支折角外都是竖线：等待的分支汇入它的圆点，或 fork 离开圆点。提交的第一个已加载父提交延续圆点的列与色相；其余每个父提交取它旁边最近的空列（已结束分支留下的列会被复用），fork 的边是从圆点到该列的斜线。跨行组合起来就是 git 的父提交边，包括合并与 fork 处的斜线。行走引用的第一父提交链始终占着最左的列，因此主干在侧枝重新并入的各个提交处始终保持同一色相。分支在其车道存续期间保持同一色相；新分支从不被占用的色相中取下一个，按六色循环轮转，因此相继的分支即使复用同一列也不同色。槽最多画六条车道，其余折到最右侧画出的那一列；所有行共用同一个槽宽，因此任何一行的文字都不会参差。父提交在已加载页之外时不画车道，因此加载下一页是在边界处延伸图形，而不是重开一张。提交行是两行 —— 第一行标题，第二行短哈希、作者与相对时间 —— 当前显示的提交带 `aria-current`。

提交页是竖向 flex 列：标题、meta、引用标签、可折叠的完整说明、改动文件区各占自身高度；对比区用 `flex: 1` 吃掉剩余高度，带 220px 下限并在内部滚动，因此短 diff 会填满整列而不是停在半截，折叠文件列表又会把空间让给对比区。文件区列状态字母、路径与行数，自身滚动盒有上限，Host 的 `maxFiles` 截断时明确说明。对比由共享的 `DiffHunks` 绘制，单栏/左右控件从 `GitPanel` 抽到 `DiffModeControl`，两个视图共用一个渲染器和一个控件。

分页是显式的：第一页请求 50 个提交，「加载更多」按已加载数量追加；部署的 `maxCommits` 若把一页压短而 `hasMore` 为真，也按同样的方式继续。没有轮询：刷新会重读引用、第一页，以及当前提交与其文件对比。列表顶部在有未提交改动时显示一行入口，按下就切到已有的 git 容器。视图是只读的：不暂存、不提交、不切换分支。

Host 侧只有一份能力，不是第二套 git 栈：`workspaceChanges` 新增 `historyRefs`、`history`、`commit` 与 `commitDiff`，全部只读，并受已有运行器上限与新的 `maxCommits`（默认 100）约束。`historyRefs` 读取本地、远程与标签引用，跳过远程的符号 `HEAD`，把附注标签 peel 到提交，并标记当前签出的分支。`history` 用这份列表校验请求的引用，用 `--skip` 与 `--max-count` 分页，返回拓扑顺序；仓库还没有提交时返回空页。`commit` 把哈希解析成提交，读取元数据与完整说明，对第一个父提交做 diff（根提交对空树），从 git 的 raw 与 numstat 记录映射重命名、二进制与状态事实，并按会话工作目录前缀过滤文件、输出相对于工作目录的路径。`commitDiff` 把单个文件与提交的第一个父提交比较，关闭外部 diff 驱动、textconv、notes 与签名显示，复用 `parsePatch`，二进制或超限时给出对应状态而不是把未过滤的输出发出去。

工作台的 Host 半在连接栅栏内注册 `/api/git.refs`、`/api/git.history`、`/api/git.commit` 与 `/api/git.commit-diff`。四条路由复用会话与工作目录检查，全部 `no-store`，校验 ref、哈希、分页与路径参数，并按已有路由的方式回答 400/404/409/503。这些读取是无状态的 route 而不是 Remote，因为它们的载荷是视图状态，不是会话传输状态。

## Alternatives considered

**三栏。** 这是参照布局，也是读者明确说不想要的那个。**否决**：在停靠面板宽度下每栏只剩 100–150px，提交列表和 diff 都不可读；而工作台已经拥有两栏语法。

**独立的历史插件包。** 最符合「一个 UI 功能一个包」的读法，但历史视图就是工作台的一个容器；独立成包需要先做活动栏的 slot 扩展点（项与容器渲染），而目前没有第二个消费者。**否决**：改动面更大。

**引用树容器。** 把引用做成第三个活动栏目的地。**否决**：引用是同一个历史之上的筛选，不是目的地；引用容器会占掉一整栏或整个视图，去回答弹层就地能回答的问题。

**一条线加合并圆环。** 一条穿过所有提交的连续线，合并提交带圆环：每个提交都可见，槽永远不会变宽，短侧枝也不会在槽里添出短线。**否决**：圆环只记录发生过合并，不能说明是哪几条线汇合 —— 读者既不能跟着一条分支离开主线，也看不到它重新并入主线。车道布局在同样窄的槽里回答了这个问题，而仓库的发布合并画出的短线段是它接受的代价。

**提交图单独一栏。** **否决**：行首窄槽已经承载车道；单独一栏会再吃掉面板四分之一，并让列表与 diff 在停靠宽度下不可读。

**在浏览器里读 git。** **否决**：客户端没有命令执行；在浏览器里解析 `.git/index` 或对象文件不值得拥有，而 Host 已经有受约束的运行器。

**复用工作区状态路由。** **否决**：status 回答的是当前工作树，不是提交；历史需要 `log`、`diff-tree`、引用列表与逐提交比较。

**滚动到底自动加载下一页。** **否决**：列表可以很长，自动加载会让刷新与切换引用和读取竞争；评审通过的原型用的是显式的「加载更多」。

**轮询历史。** **否决**：没有可以轮询的实时工作树信号，每隔几秒跑一次 `git log` 的代价大于它回答的问题；刷新是显式的。

## Consequences

视图是只读的：暂存、提交、切换分支、提交搜索、路径过滤、任意两个提交比较都未实现。合并提交显示相对第一个父提交的 diff，与文件列表的定义一致。会话工作目录是仓库子目录时，提交列表会丢弃该子目录之外的改动文件，因为路径与对比都留在会话拥有的工作区内。改动文件列表受 `maxFiles` 限制并带完整的 `total`；对比受输出上限约束，超限时报 `oversized` 而不是静默截断。刷新只重读第一页，所以通过「加载更多」装入的提交行会掉到再次按下为止；当前提交与对比会独立重读并保留。提交图最多画六条车道，因此同时打开的分支多于六条时，多出的车道折到最右侧画出的那一列；某条分支的线在它分出的提交处汇合、车道收回；短侧枝在槽里画成短线，这是车道布局为了画出父拓扑而接受的代价。所有行共用已加载行中最宽那一行的槽宽，因此每一行的文字都从同一个边缘开始。列表仍显示引用行走的每个提交，加载下一页在边界处延伸图形。

历史视图是现有 Files tab 的另一个容器，而不是新的 tab 类型，所以 tab 保持自己的身份与每 tab 的状态，三个容器共用同一条活动栏。包仍然是双面包，Host 半多四条路由；workspace-changes 多一份能力与一个 Config 字段。每个读取彼此独立且无状态，因此不需要新的 Session 释放或持久化。提交页的对比高度规则沿用原型：对比盒是弹性元素，短提交会填满整列而不是停在半截。

## Testing

单元覆盖：`ui-sidebar-files` 覆盖纯提交图布局（线性历史的单一车道、车道保持自己的列因此除圆点折角外都是竖线、fork 取最近的空列、分支末端在其分叉提交的圆点处汇合、等待车道汇合于父提交的圆点、相继分支的色相轮转、六条车道上限、下一页补出的边界线，以及空页）、引用标签与首选文件的纯函数、store 的历史切片、导航与提交页状态、引用菜单、face 的 URL 与校验处理，以及正文的 seeding、list→commit→file 链式读取、刷新、未提交行切换与窄栏返回；`workspace-changes` 覆盖引用、分页、空仓库、合并与根提交、重命名、二进制、子目录路径过滤、对比截断，以及四条服务方法背后的真实 git 仓库行为；路由测试覆盖注册、参数校验、会话/工作目录栅栏与 400/404/409/503 回答。`apps/web/tests/git-history.e2e.ts` 的浏览器覆盖在准备好的仓库上驱动真实工作台：打开历史容器，走通提交页（说明折叠、改动文件链、单栏与左右对比），按分支筛选再回到全部引用，刷新，追加下一页并打开带二进制文件的根提交，再收缩面板验证按实测宽度触发的窄栏下钻与返回控件，并断言没有页面错误。
