# 设备控制器

[English](README.md) | 中文

## 概述

`@deepseek-ai/dsh-api-device-controller` 对外提供生成的 `ctx.remote.devices` 命名空间，并实现 `dsh-client-connection` 用来认证浏览器的 `BrowserDeviceStore` 扩展点。它记录每一次启动令牌交换背后的浏览器、回答某台设备是否仍可认证，并为设置页的设备管理提供列表、重命名与吊销。记录保存在 Session 数据之外的 `browser_devices` 存储域中，因此被吊销的浏览器在 Host 重启后依然处于吊销状态。

<a id="use-this-package"></a>
## 使用本包

把本包挂载为编排了 Connection 浏览器载体的 profile 中的一个 Loader 条目。它需要 `connection` 与 `storageDomain`，且该条目属于 Web 应用包：没有载体的部署永远不会激活它，而没有面向浏览器监听器的部署也没有任何东西可记录。

认证从内存索引作答，因此 `admits` 与 `touch` 从不接触存储介质。`touch` 在每个被接纳的请求上推进实时的 `lastSeenAt`，最多每分钟持久化一次；名册是同步读取的，因为请求无法等待存储。持久名册加载完成后它就是权威依据：它不持有的设备即已被吊销。在此之前，`admits` 只在存储挂载后配置的 `rosterLoadGraceMs` 窗口内回答 true（默认十秒），因为拒绝一台名册只是还没读到的设备，会把所有浏览器锁在一个刚刚重启的部署之外；本进程自己登记的设备在这段窗口内始终被接纳。打开失败、或窗口过后仍未读出名册的情况下一律不接纳任何设备：无法作答的吊销问题不得变成一次准入，因此带着吊销记录重启的 Host 不会把已被吊销的浏览器重新放进来。

`list()` 返回所有已记录的设备，最近活跃者在前，并携带交换时观察到的 User-Agent 与对端地址。`rename(id, name)` 设置的标签最多 64 个 UTF-8 字节，留空或仅含空白则清除标签，使该行回落到根据它自己的 User-Agent 解析出的名称。`revoke(id)` 在返回前先把记录持久删除，因此该浏览器的签名 cookie 在下一次请求时不再通过认证，只有重新打开 `dsh web` 打印的链接才能回来——而且是以一台新设备的身份，因为旧行是被删除而不是留下墓碑。介质拒绝该删除时会恢复记录并报错，所以本方法报告为失败的吊销，重启后也不会被重新放进来。

名册最多保留 `maxDevices` 台设备，默认 100。登记超出上限时，最近一次认证请求最早的设备会被淘汰，其记录被持久删除，因此不断生成身份的部署不会让持久表无限增长。介质拒绝的淘汰会被记录日志，并在下次加载时重试。

本部署从未记录的 id，以及为空或长于任何已生成 id 的值，都是 `devices/unknown`。请求本身格式正确但名册拒绝（例如标签超出字节上限）是 `devices/rejected`。无法打开的名册会让每个方法都失败，这是这个异步打开的归属方能给出的最早时点。

<a id="model-experience"></a>
## 模型体验

无。浏览器认证与设备名册作用于 HTTP 请求准入，从不进入模型提示词、Session 日志或工具结果。

#### KV Cache 影响

模型请求前缀没有任何变化。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- **吊销只在已打开的 WebSocket 下次重连时生效。** 准入发生在 upgrade 时刻，而流的生命周期归 API Gateway，因此已经打开的流会持续运行到该传输重连或页面刷新为止。要在吊销时关闭已建立的流，需要一个本包并不具备的、由 Gateway 拥有的信号。
- **页面无法标出哪一行是正在阅读它的这个浏览器。** 设备 id 随签名 cookie 传递，页面读不到它；要标识当前设备，就得把它穿透 `PeerAdmission`、RPC 处理器与 Gateway 派发。因此吊销自己当前所用的浏览器会立刻把操作者退出登录，确认弹窗也如实说明了这一点。
- **页面在打开时与每次写操作后读取名册，没有 Host 事件推送变化。** 两个同时打开的设置面板要等到其中一个再次读取才会一致；`devices/changed` 转发事件需要在 API Remotes 允许列表中增加条目。
