# @deepseek-ai/dsh-client-ui-sidebar-files

English | [中文](README.zh.md)

## Summary

Browse a Session's workspace tree and read files beside it without leaving the tab: a file row opens a chip in the workbench's content column, which draws that file through the shared document preview. The root and expanded directories refresh automatically from direct-entry watches; manual reload remains available. A repository adds two read-only containers to the workbench's activity rail: the working tree's git view and the repository's commit history. The tab is reached from the guide and claims no resource address.

<a id="what-it-registers"></a>
## What it registers

The `workspace.files` command opens or focuses the file page in the focused pane; from the conversation it uses the current Session's active dock pane. A guide gives way to the file page, and repeated opens retain one file page per pane. Desktop defaults to Mod+P. The guide entry displays the effective shortcut; Windows and macOS Web use the [shortcut service’s platform defaults](../shortcuts/README.md); Linux Web leaves this command unbound by default.

- **The type** — `ctx.sidebarRightTabs.register(...)` with kind `files`, id `@deepseek-ai/dsh-client-ui-sidebar-files`, band `builtin`, no patterns, and one guide entry (order 10, its title and description from the `sidebarFiles` namespace, its glyph a yellow folder) that opens the type.
- **The body** — the keyed `sidebar.right.pane.tab` seat under that id: a header row under the strip, then the workbench. The shared [`PathLabel`](../ui-primitives/README.md#component-catalog) displays the root path with subdued directories and a primary final segment. A clipped path retains its trailing characters with a left-edge fade; hovering reveals the full path. The reload control and the Session-scoped `sidebar.right.tab.files.actions` list stay at its right, with the displayed root passed as `absolutePath`; [`ui-open-in-app`](../ui-open-in-app/README.md) contributes the workspace directory opener.
- **The chip title** — the keyed `sidebar.right.pane.tab.title` seat under that id: a shared `FileTypeIcon` folder glyph at 16px before the type's label. The tree's own rows never draw this sheet.

- **The preview** — the file the content column shows is drawn by the reusable `sidebar.document.preview` Factory of [`ui-sidebar-documentpreview`](../ui-sidebar-documentpreview/README.md#the-reusable-preview), which owns reading, renderer selection, and the document toolbar. This package passes the file's address, its absolute path as the view key, a fresh navigation revision, and the tab's abort signal as the view lifetime, so it owns no document format.

Source files under `src/client/`: `definition.tsx` (the type), `store.ts` (what it keeps), `face.ts` (Remote reads and watches), `directory-node.ts` (open directories and their lifetimes), `FilesBody.tsx` (the workbench: its header, its containers, and the preview Factory call), `tree.tsx` (the tree's rows, ordering, and failure lines), `FileTabs.tsx` (the open files' chips), `SplitView.tsx` (the two columns and their divider), `HistoryPanel.tsx` (the history view: its navigator and commit-graph rows), `CommitPage.tsx` (one commit's page), `HistoryRefsFilter.tsx` (the refs chip and its popover), `DiffModeControl.tsx` (the comparison layout control shared by the git view and the commit page), `layout.ts` (the measured narrow-layout switch every container shares), `drill-down-focus.ts` (the keyboard hand-off every narrow drill-down shares), `history.ts` and `history-graph.ts` (the pure history helpers and the commit-graph lane layout), `FilesTitle.tsx` (the chip title), `locales.ts` (what it says), and `index.ts` (the wiring, including the six git routes). `src/git.ts` holds the route paths and the validators both faces share.

<a id="the-workbench"></a>
## The workbench

The body draws two columns with a divider between them: the content column on the leading side and the tree on the trailing one. `SplitView` owns the drag: a pointer press captures the pointer, movement previews the ratio in the component's own state, and the release reports one settled ratio, which `ratioChanged` clamps to 20%–80%. The body memoizes the two columns, so a drag frame re-renders the divider and not the document behind it. The container's own measured width decides a one-column fallback below 560px (`layout.ts`): the files container then draws the tree alone, or the preview alone after a file row opens it, with a back control in the workbench header. Every drill-down in the workbench hands the keyboard over the same way (`drill-down-focus.ts`): opening or leaving one unmounts the control that held focus, so the flip moves it to the control the new view names — the back control as the drill-down opens, and the row the reader came from when the list returns, or the view's own first action when that row is gone — while a flip caused by the measured width alone moves nothing.

`FilesBody` lays the workbench out as two columns followed by a fixed activity rail at the trailing edge: the rail is a 48px column of icon-only items, one per view container — the `files` container always, and, when the working directory is inside a git work tree or git is unavailable, the `git` and `history` containers beside it. Each item carries a tooltip and an accessible name and marks the selected container; the rail never takes part in the divider, so it keeps its width while the columns resize, and its hairline sits on its leading edge. `container` records which container the rail selected, so another item extends the rail array and the store rather than the layout.

The tree column opens with a panel header: the panel title (`tree.title`, "Project") at its inline start and two icon actions at its end. Expand All (`tree.expand`) opens every directory the tree has listed, with directories that only appear in a level opened by that press following on the next press; Collapse All (`tree.collapse`) collapses every directory back to the root through the face, which ends their listings and watches while keeping the loaded levels so reopening one is instant. The commands ride `sidebar.right.pane.tab.actions` (`tab.actions.bindCommands`); the rail and the header carry `data-files-rail`/`data-files-rail-item` and `data-files-tree-header`/`data-files-tree-action` for the browser specs.

The activity rail offers a second view container when the working directory is inside a git work tree or git is unavailable: `git.status` reports `repository` or `unavailable`, and the rail then draws the git item beside the files item; an unavailable read keeps the container so its retry stays reachable. Selecting it replaces the two columns with the git view (`GitPanel`): the selected path's comparison with `HEAD` on the leading side and the changed paths grouped as Changes and Untracked Files on the trailing side (each group folds from its header and starts expanded; the group headers stick under the list's fixed header — the `Git` title, a branch chip, the reload control, and a summary line with the complete changed-file count and a synced or read-failed state — so the rows scroll beneath them), with the same draggable splitter as the files view. Below 560px of measured container width the list and the comparison become one column: the list stands alone, a row opens the comparison as a drill-down, and a back control returns to the list. On the trailing side each row carries git's status letter and file name in the kind's color — modified blue, added green, a new but still untracked file red-brown, deleted error red, renamed muted — while the containing directory keeps the row's quiet ink. The modified/added/untracked choices follow IntelliJ's file-status reading. The comparison is computed by the working-tree capability in `workspace-changes` (git's own patch against `HEAD`, and `git diff --no-index /dev/null <path>` for a path `HEAD` does not hold) and drawn by the shared numbered renderer `DiffHunks` from `ui-primitives` — the same one the turn's change review uses — so the workbench shows the project's own diff rather than a second renderer. The comparison's header carries two icon-only toggles, matching the turn's change review. The first switches layout: the press switches between one numbered column and the old and new sides beside each other scrolling together, the comparison glyph turns a quarter when the sides split, and the tooltip names the layout the press would switch to. The second switches scope: the changed hunks are the default, and a press widens the comparison to the whole file, drawing every unchanged line as context; its glyph states the shown scope and its tooltip names the scope the press switches to. Both choices are kept per tab, and switching the scope re-reads the comparison. The choice is always honoured: an addition-only or deletion-only comparison splits too, drawing the side without lines empty. Binary and oversized files are listed without lines; a repository with no uncommitted changes draws one centered clean state — in the comparison column where both are on screen, and in the single column otherwise — and a failed reload keeps the last list on screen while the summary and a banner state the failure and offer the retry. The comparison fills the remaining column height and scrolls inside its own body, so a short diff does not leave the column half empty. The panel's reload control reads the working tree again; the reload refreshes the shown comparison only while the reader stays on that path, and a path picked while the reload is in flight keeps its own read. While the view is on screen it also refreshes itself: a quiet read every three seconds that writes only when the working tree actually differs, so the rows never blank out, an unchanged tree costs no render, and a further edit to the shown file refreshes its comparison in place. A collapsed Sidebar or a hidden tab stops the reads, and coming back refreshes at once. The rail draws the history container beside the git one; the committed history is described in [its own section](#the-history-view).

The git view and the history view read six authenticated routes that this package's host half registers: `/api/git.status` and `/api/git.diff` for the working tree, and `/api/git.refs`, `/api/git.history`, `/api/git.commit`, and `/api/git.commit-diff` for the repository history. All six resolve the Session header from the id the browser sent — the live header first, the stored one second, without resuming the Session's agent — and refuse a working directory that differs from the one the header recorded, with 409; a diff or comparison route also refuses a path that escapes it. That check binds a request to a Session the Host knows; it does not bind it to the Session the requesting tab is viewing, because every browser connection shares one authenticated owner peer, so any open tab of the app can read any Session's working directory. Missing or malformed coordinates, paths, refs, page coordinates, and commit hashes answer 400, an unknown Session, commit, or comparison answers 404, and a failed repository read answers 503. Every answer carries `cache-control: no-store`, and the routes run no git code of their own — `workspaceChanges.workingTree`, `workingDiff`, `historyRefs`, `history`, `commit`, and `commitDiff` own the runner and the comparison ([service contract](../../deliverables/workspace-changes/README.md#use-this-package)).

The content column holds the open files' chips above the file the reader chose. A file row calls `fileOpened`, which appends a chip and shows that file; opening the same path again reuses its chip. The chip strip draws no scrollbar: the wheel moves it horizontally (a vertical notch scrolls the row, a line-mode or horizontal delta is honoured, and a strip with nothing hidden leaves the notch to its ancestors), a chip that opens or becomes the shown one past the strip's edge is scrolled back into view without moving any ancestor, and each hidden edge fades the chips out over 24px so the row reads as continuing. Chips shrink only to a 100px floor, so a long row overflows instead of shrinking away. A chip click calls `fileActivated`; its close control (or a middle click) calls `fileClosed`, which shows the next chip, or the previous one when the closed chip was last, and empties the column when the last chip goes. A secondary press opens the chip's menu: Close, Close Other Tabs, Close All Tabs, Close Tabs to the Left, and Close Tabs to the Right call `fileClosed`, `filesClosedExcept`, `filesClosedAll`, `filesClosedBefore`, and `filesClosedAfter`, and each arm that would remove nothing is disabled rather than hidden. After those arms come the rows other plugins contribute to `sidebar.right.tab.files.chip.actions`, where `ui-open-in-app` puts a reveal row that hands the file's folder to the desktop file manager. That empty state names where files come from rather than showing a blank column.

The file is drawn by `renderFactorySlot('sidebar.document.preview', { address, viewKey, navigation, signal })`: the store keeps the absolute path, the address is built by `fileAddressFor` from `@deepseek-ai/dsh-util-workspace-path`, and the view key prefixes the file's absolute path with the tab id, so two workbench tabs over the same file keep their scroll, zoom, wrap, and viewer choice apart, because the Factory buckets its state by the view key. Delivering a file this preview cannot render, a file whose Host path is unknown, and a binary container with no registered renderer are the Factory's own states, unchanged from a Sidebar preview tab.

Everything the workbench keeps lives in the type's own store, bucketed by tab id: `root`, `levels`, `expanded`, `scrollTop`, `autoRefresh`, the open files (`open`), the shown path (`active`), the rail's selected container (`container`), the git view (`git`: its last status, the shown path, that path's comparison, its layout choice, and the narrow drill-down's open state), the history view (`history`: the refs and the walked ref, the loaded commit pages and whether more follow, the shown commit with its changed files, the file section's fold, that file's comparison, the comparison layout, the pane ratio, both scroll offsets, and the narrow drill-down's open state), `ratio`, and the files container's narrow preview-drill-down state (`pageOpen`). Because the store outlives the body, switching to another sidebar tab and back remounts the workbench with its chips, its shown file, its git or history selection, its divider position, and its tree intact.

<a id="the-tree"></a>
## The tree

The root is the session's working directory, read from `useSessions().byId[sessionId].cwd`. Filesystem roots such as `/` and Windows drive roots are valid tree roots. Every level is keyed by absolute path; a child's path is its parent's joined with the entry name by `/`. A level is listed when it is first expanded, through `remote.workspaceFiles.list(sessionId, absolutePath)` on the `@deepseek-ai/dsh-api-workspace-files` namespace; the adapter keeps the listing's entries and truncation flag and drops its workspace-relative path. Rows are ordered directories first, then by natural, case-insensitive name; dotfiles are shown like any other entry.

| Entry type | Row |
|---|---|
| `directory` | Toggles; reopening lists again and restores still-present expanded descendants. Displayed entries remain cached while collapsed. |
| `file` | Calls `fileOpened` with the entry's absolute path, its `dsh-resource://file/session/<sessionId>/<encoded path relative to the root>` address (built by `fileAddressFor`), and its name: the file joins the content column's chips and becomes the shown one. The row marks the shown file, so the tree answers where the reader is. |
| `other` | Shown greyed and not clickable, so the directory is reported whole. |

A level cut by the endpoint's entry cap ends with a marker; an empty level says so; a level that failed shows one line per code — `workspace-file/not-found`, `outside-workspace`, `not-directory` — and the transport's own message otherwise. Reload refreshes the root and expanded levels in place, retaining displayed entries during reads instead of resetting the whole tree; collapsed levels are fetched again when they next open. A session without a working directory shows a single line instead of a tree.

State lives in the type's own store, bucketed by tab id: `root`, `levels` (loading / ready / failed per absolute path), `expanded`, `autoRefresh`, and `scrollTop`, which the body tracks locally while scrolling and commits once when it unmounts. The tree's levels and its scroll offset outlive the body, so a remounted workbench draws them as they were. The owner's `signal` ends a bucket: on abort the tab is forgotten, and neither a listing that settles afterwards nor the unmount's offset commit writes anything.

Each open `DirectoryNode` owns its target watch for the Tab lifetime; collapse closes that node and its hidden descendants. Expansion changes during ancestor restoration update the store and pending nodes, so restored descendants follow the latest expansion preferences. Automatic refresh defaults to enabled; its separate toggle is hidden while state, labels, styles, and toggle logic remain. Changes received during a directory read or its completion remain pending for another refresh.

<a id="the-history-view"></a>
## The history view

The rail's `history` item (a clock glyph) replaces the workbench's columns with `HistoryPanel`; it is offered under the same condition as the git item, and both rest on the one status read. The wide layout is two panes joined by the workbench's divider: the selected commit's page on the leading side and the navigator on the trailing one, with the page's share kept per tab. Below a panel width of 560px — measured on the panel's own box with a `ResizeObserver`, not derived from a window media query — the view is one column: the navigator draws alone, a commit row drills into its page, and a back control returns to the list. A hidden or not-yet-laid-out panel keeps the wide layout, so one window holds both layouts as the reader resizes the Sidebar.

The navigator carries the "History" title, the refs chip, and a reload control above its scroller, so the rows scroll beneath a fixed header. Its first row is the working tree's uncommitted-changes row, shown only while the list walks all refs and the status read found changes; activating it switches the rail to the git container, which owns those changes. Commit rows follow, each with its commit-graph gutter, the commit's refs as pills (the attached branch first, then local, remote, and tag names; at most two names plus a `+n` pill), the subject, and a second line with the abbreviated hash, the author, and the relative author date whose title states the absolute date. The shown commit's row carries `aria-current`. One page holds `HISTORY_PAGE_SIZE` (50) commits — the same constant the history route serves a request that names no limit; an explicit "Load more" row reads the next page while the ref has commits after the loaded pages, and a reload that fails keeps the drawn rows, states the failure above them, and offers its retry.

The gutter draws the loaded commits' commit graph: `layoutGraph` (`history-graph.ts`) is a pure lane layout, and each row draws the lane segments that cross it and its commit dot, with a ring around the shown commit's dot. Every child keeps its own lane waiting for its parent, so several lanes can wait for one commit, and at that commit's row they meet at its dot: the leftmost waiting lane becomes the dot and the others draw a diagonal from the row's top into it, so a branch's line runs to the dot of the commit it branched from instead of ending between two rows. Each lane keeps its column until the commit it waits for arrives, so a segment away from a dot is vertical and a slanted segment exists only at a branch corner: a fork leaving a dot, or a waiting branch meeting the dot it branched from. A commit's first loaded parent continues the dot's column and hue; each further parent takes the nearest free column beside it, reusing a column an ended branch left, and the fork edge is the diagonal from the dot to that column. Free columns can therefore sit between two open lanes until a later branch takes them. Across rows, the segments compose git's parent edges.

The walked ref's first-parent chain always keeps the leftmost lane, so the mainline reads in one hue through the commits its side branches merge back into. A branch keeps its hue for the life of its lane, and a new branch takes the next hue no open lane uses from a rotating sequence of six — indigo, green, amber, red, violet, teal — so simultaneous lanes never share a hue. At most six lanes are drawn: a lane past the cap clamps into the rightmost drawn column. Rows are 44px tall on a 9px lane pitch, and every row shares the navigator's one gutter width — 16px for one lane up to 61px for six — so no row's text starts at another edge. The gutter is an inline SVG at the row's leading edge, never its own column, and it is not interactive: the row's selection owns the gesture. The list still shows every commit in git's order, and loading another page extends the same graph rather than restarting it: the boundary row is continuous, so a parent outside the loaded page draws no lane until it arrives, and that row gains its outgoing line when it does. Rows already above the boundary can still move when a later page names a parent they could not place, because the lane order depends only on the commits loaded above them.

The refs chip opens a searchable popover listing "All refs" (which walks the repository's `HEAD`) and the refs the refs read returns, grouped into local branches, remotes, and tags; the search filters rows by name and reports when nothing matches. Picking a ref restarts the list at that ref's newest commit and clears the shown page; "All refs" returns to `HEAD`. The filter changes only which history the list walks — it never switches the repository's branch, and the popover states that. A failed refs read is retried from the popover, and the chip names the walked ref so the list's scope is visible above it. Every ref name the view draws — a row pill, the commit page's pill, a filter row and its hover title, the chip — drops the Unicode bidi embedding, override, and isolate controls (`refDisplayName`), because git accepts them inside a ref name and a repository can therefore hold a tag that renders as a different name than the one it is.

The commit page draws the selected commit's message — the body after the subject folds behind a toggle — and a meta line with the abbreviated hash, author, relative date, and up to four ref pills plus `+n`. Its changed-file section states the commit's complete file count, adding the commit's added and deleted totals only when the Host returned every changed file; it then lists each file with git's letter (A, D, M, or R, colored by kind), path, and `+`/`−` counts or a "Binary" label. Folding the section leaves its header drawn and names the file whose comparison is shown, and a note reports how many of how many files the Host's file cap returned. The selected file's comparison is drawn by the shared numbered `DiffHunks` renderer — the same one the working-tree git view and the turn's change review use — and switched between a unified column and side-by-side sides by the shared icon-only `DiffModeControl` toggle beside the shared scope toggle that draws the changed hunks by default, with both choices kept per tab. A created file draws its whole content with a created note, and a binary file, an oversized file, and a file with no lines each have their own filled state. The page is a flex column whose comparison takes the remaining height with its own scroll, so a one-line change fills the column instead of leaving it half empty, and folding the file section gives the comparison more room.

The container seeds its reads on open: the refs first, then the first page of the walked ref. A loaded page selects its first commit, and a loaded commit selects its first changed file — a source file under a `src` directory first, then another code or data file, then the file in the Host's order — so the wide layout opens on content without a gesture. Every read follows a gesture, and a gesture's read supersedes the one it replaces; the reload control re-reads the refs, the shown commit, and that commit's selected comparison. History does not poll: a commit made while the tab is open appears after a reload, and a reload reads only the first page, so rows the reader loaded from later pages drop until they are loaded again. The list keeps its scroll offset across container switches, the commit page keeps its offset for the commit it draws, and walking another ref starts the list at the top.

The four history routes read only: nothing in the view stages, commits, checks out, discards, or rewrites anything, and the dirty-changes row leaves the history view rather than acting on the working tree.

## Model Experience

None, as this package draws workspace files, the working tree, and repository history in the browser and registers nothing model-facing.

#### KV Cache effect

None; directory listings and repository reads travel over the Remote and assemble no model request.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>
- **Listing only.** No search, artifact filter, drag-and-drop, or rename in the tree.
- **The git and history views are read-only.** They list the working tree and the repository's commits and draw comparisons; staging, committing, switching or creating branches, discarding, and rewriting history are not built. Picking a ref in the history filter never checks anything out.
- **The history list pages at 50 and reloads only the first page.** Rows loaded from later pages drop on a reload, and a commit made while the tab is open appears only after one, because history reads do not poll.
- **The git summary has no line counts.** The working-tree status route carries paths and kinds, not added and deleted lines, so the changed-path list and its summary report the complete change count and the sync state without per-file totals.
- **A merge commit compares against its first parent.** Its page shows what the merge introduced relative to the commit it merged into; comparing two arbitrary commits is not built.
- **A subdirectory session sees its own subtree.** When the Session's working directory is below the repository root, history lists and compares only paths inside it: a commit that changed only files above the working directory shows an empty changed-file section, and a rename whose origin lies outside drops the origin.
- **The changed-file list is capped by the Host.** A commit with more changed files than the `workspace-changes` `maxFiles` setting shows the first ones, states the complete count, and omits its added/deleted totals; the setting and the complete first-parent and subdirectory rules belong to [that service](../../deliverables/workspace-changes/README.md#use-this-package).
- **The commit graph draws at most six lanes.** A lane past the sixth clamps into the rightmost drawn column, so a history with more open branches than that shows those lanes sharing the last column; the list still shows every commit in git's order.
- **No history search or path filter.** The navigator only walks one ref's commits by paging: there is no commit-message search, path or author filter, or two-commit comparison.
- **Expand All is one generation deep.** It opens every directory the tree has already listed; a directory that first appears in a level opened by that press needs a second press.
- **The dividers are pointer-only.** The files, git, and history splits expose `role="separator"` but no keyboard route to move them.
- **One content column.** The files container keeps one content column; a split editor is not built, and a narrow pick is a preview drill-down rather than a second column.
- **One root.** The tree is rooted at the session's working directory; there is no way to browse above it, and the Host refuses paths outside the workspace root anyway.
