# @deepseek-ai/dsh-client-ui-sidebar-files

English | [中文](README.zh.md)

## Summary

Browse a Session's workspace tree beside the files you preview. Each pane, docked or floating, keeps one tree that keeps its width, expansion, and scroll across file changes and marks the current file. A preview's tree opens a file in place of that preview; the `files` page, reached from the guide, is a workbench whose tree opens a file as a chip in its content column, and it claims no resource address. Watched directories refresh automatically, and manual reload remains available. A repository adds a read-only git view and commit history to the workbench's activity rail.

## What it registers

The `workspace.files` command shows the navigator drawn beside a docked tab's content in the focused pane and moves keyboard focus to its tree, keeping the tab; from the conversation it uses the current Session's active dock pane. Elsewhere — the files page itself, a tab without the navigator, a Session without a working directory, a floating tab — it opens or focuses the files page, whose tree always shows. A guide gives way to the files page, and repeated opens retain one files page per pane. Desktop defaults to Mod+P. The guide entry displays the effective shortcut; Windows and macOS Web use the [shortcut service’s platform defaults](../shortcuts/README.md); Linux Web leaves this command unbound by default.

- **The type** — `ctx.sidebarRightTabs.register(...)` with kind `files`, id `@deepseek-ai/dsh-client-ui-sidebar-files`, band `builtin`, no patterns, and one guide entry (order 10, its title and description from the `sidebarFiles` namespace, its glyph a yellow folder) that opens the type.
- **The page body** — the keyed `sidebar.right.pane.tab` seat under that id. Its header row spans the page and shows the root through the shared [`PathLabel`](../ui-primitives/README.md#component-catalog) with subdued directories and a primary final segment; a clipped path retains its trailing characters with a left-edge fade, and hovering reveals the full path. The tree's reload control, the Session-scoped `sidebar.right.tab.files.actions` list, which the page's registration declares, with the displayed root passed as `absolutePath`, follow at its end, in the order a preview's header ends with its reload and file actions; [`ui-open-in-app`](../ui-open-in-app/README.md) contributes the workspace directory opener. [The workbench](#the-workbench) fills the page below the header, docked or floating; its tree column is the pane's navigator, which has no toggle there.
- **The rows** — the root-scoped Component Factory `sidebar.files.tree`, with caller-owned entries and a local `accessory` slot; see [Reusable tree Factory](#tree-factory).
- **The navigator** — the Session-scoped Component Factory `sidebar.files.navigator`, rendered directly by the workbench's tree column and by [`ui-sidebar-documentpreview`](../ui-sidebar-documentpreview/README.md) beside every preview, docked or floating. It draws the tree, and beside a preview its resize edge, without a header of its own: beside a preview the preview's header is the only one, and the tree's reload and directory actions stay on the `files` page.
- **The toggle** — the Session-scoped Factory `sidebar.files.navigator.toggle`, rendered directly at the end of the preview header with `useTabInfo`. Both Factories share the page's store handle and inject face, retaining one open choice per pane; the page body has no toggle.
- **The preview** — the Session-scoped single seat `sidebar.right.tab.files.preview`, which the page's registration declares and the workbench's content column renders. [`ui-sidebar-documentpreview`](../ui-sidebar-documentpreview/README.md#the-reusable-preview) fills it with its reusable `sidebar.document.preview` Factory, which owns reading, renderer selection, and the document toolbar, so this package owns no document format.
- **The chip title** — the keyed `sidebar.right.pane.tab.title` seat under that id: a shared `FileTypeIcon` folder glyph at 16px before the type's label. The tree's own rows never draw this sheet.
- **The row menu arms** — contributions to the shared context menu's `file` and `directory` targets: Open, or Expand and Collapse, then Copy relative path on a tree row; see [The tree](#the-tree).

The [registration](src/client/index.ts) assembles the page, navigator, toggle, and tree Factories over the shared [files face](src/client/face.ts) and [store](src/client/store.ts), which keeps one record per pane and one per `files` tab.

Source files under `src/client/`: `definition.tsx` (the type), `store.ts` (what it keeps), `face.ts` (Remote reads and watches, and each pane's reveal, focus, and measured row), `directory-node.ts` (open directories and their lifetimes), `workspace-tree.ts` (a pane's listed levels as the tree's entries), `FileTree.tsx` (the tree Factory's rows, ordering, and failure lines), `FileNavigator.tsx` (one pane's navigator), `NavigatorToggle.tsx` (the preview header's toggle), `navigator-layout.ts` (the navigator's width rules), `FilesBody.tsx` (the workbench: its header, its containers, the tree column, and the preview seat), `WorkbenchRail.tsx` (the activity rail), `FileTabs.tsx` (the open files' chips), `SplitView.tsx` (the two columns and their divider), `GitPanel.tsx` (the git view), `HistoryPanel.tsx` (the history view: its navigator and commit-graph rows), `CommitPage.tsx` (one commit's page), `HistoryRefsFilter.tsx` (the refs chip and its popover), `RefPills.tsx` (the ref pills a history row and the commit page share), `DiffModeControl.tsx` and `DiffScopeControl.tsx` (the comparison layout and scope toggles shared by the git view and the commit page), `layout.ts` (the measured narrow-layout switch every container shares), `drill-down-focus.ts` (the keyboard hand-off every narrow drill-down shares), `use-scroll-restore.ts` (a pane's scroll offset across unmounts), `use-now.ts` (the history view's minute clock), `history.ts` and `history-graph.ts` (the pure history helpers and the commit-graph lane layout), `FilesTitle.tsx` (the chip title), `locales.ts` (what it says), and `index.ts` (the wiring, including the row menu arms). `src/index.ts` registers the six git routes, and `src/git.ts` holds the route paths and the validators both faces share.

<a id="the-workbench"></a>
## The workbench

The body draws two columns with a divider between them: the content column on the leading side and the tree on the trailing one. `SplitView` owns the drag: a pointer press captures the pointer, movement previews the ratio in the component's own state, and the release reports one settled ratio, which `ratioChanged` clamps to 20%–80%. The body memoizes the two columns, so a drag frame re-renders the divider and not the document behind it. The container's own measured width decides a one-column fallback below 560px (`layout.ts`): the files container then draws the tree alone, or the preview alone after a file row opens it, with a back control in the workbench header. Every drill-down in the workbench hands the keyboard over the same way (`drill-down-focus.ts`): opening or leaving one unmounts the control that held focus, so the flip moves it to the control the new view names — the back control as the drill-down opens, and the row the reader came from when the list returns, or the view's own first action when that row is gone — while a flip caused by the measured width alone moves nothing.

`FilesBody` lays the workbench out as two columns followed by a fixed activity rail at the trailing edge: the rail is a 48px column of icon-only items, one per view container — the `files` container always, and, when the working directory is inside a git work tree or git is unavailable, the `git` and `history` containers beside it. Each item carries a tooltip and an accessible name and marks the selected container; the rail never takes part in the divider, so it keeps its width while the columns resize, and its hairline sits on its leading edge. `container` records which container the rail selected, so another item extends the rail array and the store rather than the layout.

The tree column opens with a panel header: the panel title (`tree.title`, "Project") at its inline start and two icon actions at its end. Expand All (`tree.expand`) opens every directory the tree has listed, with directories that only appear in a level opened by that press following on the next press. Collapse All (`tree.collapse`) collapses every directory back to the root through the face, which ends their listings and watches while keeping the loaded levels, so a reopened directory draws its kept rows at once; it also ends a reveal in progress, so the tree does not reopen toward the shown file. Both act on the pane's tree, so a preview's navigator in the same pane follows them. The rail and the header carry `data-files-rail`/`data-files-rail-item` and `data-files-tree-header`/`data-files-tree-action` for the browser specs.

The activity rail offers a second view container when the working directory is inside a git work tree or git is unavailable: `git.status` reports `repository` or `unavailable`, and the rail then draws the git item beside the files item; an unavailable read keeps the container so its retry stays reachable. Selecting it replaces the two columns with the git view (`GitPanel`): the selected path's comparison with `HEAD` on the leading side and the changed paths grouped as Changes and Untracked Files on the trailing side (each group folds from its header and starts expanded; the group headers stick under the list's fixed header — the `Git` title, a branch chip, the reload control, and a summary line with the complete changed-file count and a synced or read-failed state — so the rows scroll beneath them), with the same draggable splitter as the files view. Below 560px of measured container width the list and the comparison become one column: the list stands alone, a row opens the comparison as a drill-down, and a back control returns to the list. On the trailing side each row carries git's status letter and file name in the kind's color — modified blue, added green, a new but still untracked file red-brown, deleted error red, renamed muted — while the containing directory keeps the row's quiet ink. The modified/added/untracked choices follow IntelliJ's file-status reading. The comparison is computed by the working-tree capability in `workspace-changes` (git's own patch against `HEAD`, and `git diff --no-index /dev/null <path>` for a path `HEAD` does not hold) and drawn by the shared numbered renderer `DiffHunks` from `ui-primitives` — the same one the turn's change review uses — so the workbench shows the project's own diff rather than a second renderer. The comparison's header carries two icon-only toggles, matching the turn's change review. The first switches layout: the press switches between one numbered column and the old and new sides beside each other scrolling together, the comparison glyph turns a quarter when the sides split, and the tooltip names the layout the press would switch to. The second switches scope: the changed hunks are the default, and a press widens the comparison to the whole file, drawing every unchanged line as context; its glyph states the shown scope and its tooltip names the scope the press switches to. Both choices are kept per tab, and switching the scope re-reads the comparison. The choice is always honoured: an addition-only or deletion-only comparison splits too, drawing the side without lines empty. Binary and oversized files are listed without lines; a repository with no uncommitted changes draws one centered clean state — in the comparison column where both are on screen, and in the single column otherwise — and a failed reload keeps the last list on screen while the summary and a banner state the failure and offer the retry. The comparison fills the remaining column height and scrolls inside its own body, so a short diff does not leave the column half empty. The panel's reload control reads the working tree again; the reload refreshes the shown comparison only while the reader stays on that path, and a path picked while the reload is in flight keeps its own read. While the view is on screen it also refreshes itself: a quiet read every three seconds that writes only when the working tree actually differs, so the rows never blank out, an unchanged tree costs no render, and a further edit to the shown file refreshes its comparison in place. A collapsed Sidebar or a hidden tab stops the reads, and coming back refreshes at once. The rail draws the history container beside the git one; the committed history is described in [its own section](#the-history-view).

The git view and the history view read six authenticated routes that this package's host half registers: `/api/git.status` and `/api/git.diff` for the working tree, and `/api/git.refs`, `/api/git.history`, `/api/git.commit`, and `/api/git.commit-diff` for the repository history. All six resolve the Session header from the id the browser sent — the live header first, the stored one second, without resuming the Session's agent — and refuse a working directory that differs from the one the header recorded, with 409; a diff or comparison route also refuses a path that escapes it. That check binds a request to a Session the Host knows; it does not bind it to the Session the requesting tab is viewing, because every browser connection shares one authenticated owner peer, so any open tab of the app can read any Session's working directory. Missing or malformed coordinates, paths, refs, page coordinates, and commit hashes answer 400, an unknown Session, commit, or comparison answers 404, and a failed repository read answers 503. Every answer carries `cache-control: no-store`, and the routes run no git code of their own — `workspaceChanges.workingTree`, `workingDiff`, `historyRefs`, `history`, `commit`, and `commitDiff` own the runner and the comparison ([service contract](../../deliverables/workspace-changes/README.md#use-this-package)).

The content column holds the open files' chips above the file the reader chose. A file row's click, or its menu's Open row, calls `fileOpened`, which appends a chip and shows that file; opening the same path again reuses its chip. The chip strip draws no scrollbar: the wheel moves it horizontally (a vertical notch scrolls the row, a line-mode or horizontal delta is honoured, and a strip with nothing hidden leaves the notch to its ancestors), a chip that opens or becomes the shown one past the strip's edge is scrolled back into view without moving any ancestor, and each hidden edge fades the chips out over 24px so the row reads as continuing. Chips shrink only to a 100px floor, so a long row overflows instead of shrinking away. A chip click calls `fileActivated`; its close control (or a middle click) calls `fileClosed`, which shows the next chip, or the previous one when the closed chip was last, and empties the column when the last chip goes. A secondary press opens the chip's menu: Close, Close Other Tabs, Close All Tabs, Close Tabs to the Left, and Close Tabs to the Right call `fileClosed`, `filesClosedExcept`, `filesClosedAll`, `filesClosedBefore`, and `filesClosedAfter`, and each arm that would remove nothing is disabled rather than hidden. After those arms come the rows other plugins contribute to `sidebar.right.tab.files.chip.actions`, where `ui-open-in-app` puts a reveal row that hands the file's folder to the desktop file manager. That empty state names where files come from rather than showing a blank column.

The file is drawn by the plugin that fills the Session-scoped `sidebar.right.tab.files.preview` seat, which receives `{ address, viewKey, navigation, signal, paneId }`: the store keeps the absolute path, the address is built by `fileAddressFor` from `@deepseek-ai/dsh-util-workspace-path`, and the view key prefixes the file's absolute path with the tab id, so two workbench tabs over the same file keep their scroll, zoom, wrap, and viewer choice apart, because the `sidebar.document.preview` Factory buckets its state by the view key. `signal` is the open chip's own preview lifetime, so closing a chip releases its preview without touching its siblings, and `paneId` names the pane for the preview header's file menu; the seat carries no `useTabInfo`, because the workbench draws its own navigator. With `ui-sidebar-documentpreview` filling the seat, a file this preview cannot render, a file whose Host path is unknown, and a binary container with no registered renderer are the Factory's own states, unchanged from a Sidebar preview tab.

Everything else the workbench keeps lives in the type's own store, in one record per `files` tab: `root`, the open files (`open`), the shown path (`active`), the rail's selected container (`container`), the git view (`git`: its last status, the shown path, that path's comparison, its layout choice, and the narrow drill-down's open state), the history view (`history`: the refs and the walked ref, the loaded commit pages and whether more follow, the shown commit with its changed files, the file section's fold, that file's comparison, the comparison layout, the pane ratio, both scroll offsets, and the narrow drill-down's open state), `ratio`, and the files container's narrow preview-drill-down state (`pageOpen`); the tree is the pane's record, described under [The tree](#the-tree). Because the store outlives the body, switching to another sidebar tab and back remounts the workbench with its chips, its shown file, its git or history selection, its divider position, and its tree intact. The tab's abort signal ends its record: on abort the tab is forgotten, every chip's preview lifetime ends, and a git or history read that settles afterwards writes nothing.

<a id="the-navigator"></a>
## The navigator

Render `sidebar.files.navigator` with `FileNavigatorInput`: `{ useTabInfo, page, onOpen, current? }`. The required `onOpen: (address: string, path: string) => void` callback receives a picked file's address and absolute path and belongs to the containing plugin, which decides what an open means; the navigator builds the file address without choosing placement. `page` controls presentation only: `true` always fills the files page's tree column, while `false` follows the preview's pane preference and available width. `current` is the address the tree marks and reveals, the tab's own content when omitted; the files page passes the file its content column shows.

The navigator is drawn below the preview's header, which spans the pane, at the right of the row it shares with the body. Beside a preview, its pane's record decides whether it shows: a pane starts with it hidden, and the choice holds for every file tab of the pane until the toggle, Escape, the workspace command, or navigation to a covered preview changes it. A pane without a record of its own, such as a floating panel a tab was dragged out into, starts hidden at the default width. A click outside the tree does not hide it, and opening content in another pane does not hide it either. On the files page the tree fills the workbench's tree column, docked or floating, without a separator, and always shows: the page draws no toggle and Escape leaves it.

On the files page the workbench's divider sets the tree column's width. Beside a preview, its width is the pane's preference, 260px until the reader drags the separator on its left edge with the primary button or moves it with the arrow keys, Home (narrowest), or End (widest), clamped to the row: at least 180px when the row allows it, and at most the row's width less 336px where the navigator sits beside the body and less 120px where it floats. Beside a preview in a viewport at least 768px wide, the row's width, measured by the face, picks one of three layouts. From 560px on, the navigator is a raised panel beside the body, 8px inside the row's top, right, and bottom edges and 8px clear of the body, which narrows by the panel and its margins but keeps at least 320px. From 400px up to 560px, the same panel floats over the body's right part, so the body keeps its full width and the part the panel leaves uncovered stays scrollable and interactive; the panel covers the body's scrollbar and a renderer's sticky toolbar where they run beneath it. Both panels have rounded corners, the floating dock panel's surface and shadow in light mode, and the compact tree's dark background with a soft white shadow in dark mode. The 560px threshold depends on the row alone, so resizing the tree never moves it between the two layouts. In a row narrower than 400px, or a viewport narrower than 768px, where the right Sidebar presents its panel fullscreen, the navigator fills the row below the header without the separator, and navigation to that preview hides the tree so the file shows. While filled, the covered body is hidden from keyboard navigation, including embedded frames. If the body holds focus when the row or viewport enters this layout, including the tree's first drawing, focus moves into the tree without changing the pane's open choice. The browser may blur the hidden body before the new width is reported; that focus also moves into the tree unless the reader moves the keyboard or the pointer, or the window loses focus, before the report. Docked and floating panes follow the same rules; the floating pane's resize handle remains reachable with the tree open in every layout. Beside a preview, an unmodified Escape that reaches the page's document from the body or the tree in the row closes the navigator at any row width and moves keyboard focus to the toggle; a key pressed while an embedded frame's document holds focus does not bubble to the page's document, so it leaves the navigator open. Escape is heard on the document after the row's own handlers, so a handler in the row that prevents it keeps it.

The preview's `onOpen` passes [`replaceTab: true`](../ui-sidebar-right/README.md#ctxsidebarright), and the right Sidebar owns the replacement and reveal; a replacement retains the pane's tree. The files page's `onOpen` opens the file as a chip in the page's own content column, so a pick from the page never leaves it. When the tree holds keyboard focus and an open replaces or switches the tab in the same pane, or changes the file a wide files page shows, the next drawing focuses the current file's row; revealing another pane leaves the initiating tree and its focus unchanged.

A new `tab.navigation.revision` closes only the destination preview's tree, and only when it covers the content row at the destination's current width. The rule applies to every navigation source, including an open from that floating preview's own tree. Hidden trees consume navigation too, so manually showing one does not replay an old close. Ordinary tab switches, floating or docking, and revision `0` restored by reload or undo do not close the tree. The files face retains consumption records for the tab lifetime; navigation subscriptions end on tab closure or plugin disposal. The page's always-visible tree is not closed by navigation.

The tree marks the row of the current file with `aria-current`. While the tree is drawn, a file not yet revealed in the pane has its ancestors expanded one listed level at a time and its row scrolled into view; a kept level that is being listed again, as when a hidden tree shows or a collapsed directory reopens, is waited for before a name missing from it ends the reveal; the pane remembers the file it revealed last, so a remount of the same tab changes neither expansion nor scroll. A directory the reader collapses during a reveal ends it, and the pane counts the file as revealed. A file outside the workspace root, or one of another Session, is not located; under a Windows drive or UNC root, containment ignores case and separator spelling, and under a POSIX root it is case-sensitive. On the files page the current file is the one its content column shows, so switching chips reveals the newly shown file the same way.

<a id="the-tree"></a>
## The tree

The root is the session's working directory, read from `useSessions().byId[sessionId].cwd`. Filesystem roots such as `/` and Windows drive roots are valid tree roots. Every level is keyed by absolute path; a child's path is its parent's joined with the entry name by `/`. A level is listed when it is first expanded, through `remote.workspaceFiles.list(sessionId, absolutePath)` on the `@deepseek-ai/dsh-api-workspace-files` namespace. The rows are drawn by the [tree Factory](#tree-factory), which orders them; `workspace-tree.ts` passes every listed entry with its listing's name and type as `meta.kind`, the root key without trailing separators, and localized failure lines. The Factory reads its own copy from the files locale. Dotfiles are shown like any other entry.

| Entry type | Row |
|---|---|
| `directory` | Toggles; reopening lists again and restores still-present expanded descendants. Displayed entries remain cached while collapsed. |
| `file` | Opens `dsh-resource://file/session/<sessionId>/<encoded path relative to the root>`, built by `fileAddressFor` from `@deepseek-ai/dsh-util-workspace-path` from the entry's absolute path and the tree's root, through the containing plugin's `onOpen` as [the navigator](#the-navigator) describes: the files page adds the file to its content column's chips and shows it, and a preview's tree opens it in place of that preview. While no registered tab type can open that address, for example without `ui-sidebar-documentpreview`, the row is shown greyed and not clickable with a line saying so, and it becomes clickable as soon as a type that opens it registers. |
| `other` | Shown greyed and not clickable, so the directory is reported whole. |

A level cut by the endpoint's entry cap ends with a marker; an empty level says so; a level that failed shows one line per code — `workspace-file/not-found`, `outside-workspace`, `not-directory` — and the transport's own message otherwise. Reload refreshes the root and expanded levels in place, retaining displayed entries during reads instead of resetting the whole tree; collapsed levels are fetched again when they next open. A session without a working directory shows a single line instead of a tree.

State lives outside the drawing, keyed by the pane id that `useTabInfo().panel` reports. The type's own store holds, per pane, the navigator's `open` choice and `width`, and its `tree` once first shown: `root`, `levels` (loading / ready / failed per absolute path, a ready level marked `refreshing` while it is listed again), `expanded`, and `autoRefresh`. Every file tab of a pane reads the same record, so switching, opening, or closing tabs redraws the navigator with its levels, expansion, width, and scroll intact; a tab switch lists nothing again. Hiding the tree, or showing only tabs without it, closes its directory watches; showing it again lists the root and the expanded directories again in place while their kept rows stay drawn. A tree rooted at a directory other than the Session's current working directory is replaced, and its scroll position and revealed file are reset. A pane keeps its tree while it shows the navigator or holds an open tab that last drew the navigator there: a file tab moved to another pane shows that pane's tree, a tab replaced in place, as a picked file replaces a preview, keeps it, and floating or docking a tab never ends it by itself. Once the last such tab closes or draws the navigator elsewhere, the pane's tree is forgotten. The page and every preview's navigator share one face per Session and one workspace tree per pane; the page's workbench keeps its own record per tab, described under [The workbench](#the-workbench).

Each open `DirectoryNode` owns its target watch while the tree is drawn; collapse closes that node and its hidden descendants. Expansion changes during ancestor restoration update the store and pending nodes, so restored descendants follow the latest expansion preferences. Automatic refresh defaults to enabled; its separate toggle is hidden while state, labels, styles, and toggle logic remain. Changes received during a directory read or its completion remain pending for another refresh.

File rows expose the shared [context menu](../ui-context-menu/README.md) with its `file` target, carrying the pane id, without invoking ordinary click navigation. Directory rows and the root path use the `directory` target for native reveal and path copying without expanding the tree. On a menu a tree row raises, this package adds Open on a file row, which does what the row's click does, and Expand or Collapse on a directory row, named for the press's effect; both sort at order 50, before the rows `ui-open-in-app` contributes at order 100. Copy relative path follows at order 150: it copies the row's path below the workspace root and reports "Copied", or a failure line when the clipboard refuses. The same targets raised elsewhere, such as the root path, carry none of these rows.

<a id="tree-factory"></a>
## Reusable tree Factory

To draw workspace listings, changed files, or local diffs, declare `const TREE_OPTIONS = { slots: { accessory: ModuleLevelComponent }, fallback: null }` at module scope, then call `renderFactorySlot('sidebar.files.tree', input, TREE_OPTIONS)`. Keep the options and its `slots` object stable; recreating the local selection makes the whole tree redraw on parent renders. The root-scoped Factory is available only while the files plugin is loaded; without it, `renderFactorySlot` renders the supplied `fallback`, or nothing when omitted. Import declarations and `FileTreeInput`, `TreeEntry`, `TreeEntryMeta`, `TreeEntryKind`, and `TreeDirectoryState` type-only from `@deepseek-ai/dsh-client-ui-sidebar-files/client`; no component value is exported.

`FileTreeInput` carries `root`, flat `entries`, `expanded`, `onToggle(entry, expanded)`, and `onOpen(entry)`. Optional `directories` supplies loading, localized failure, and truncation states by key; `current` and `currentRef` mark and expose the current file button. `canOpen(entry)` can refuse a file without disabling its accessory. `rowTriggerProps(entry, kind)` supplies context menu handlers for directory rows and openable file rows. The Factory owns loading, empty, truncated, and unavailable copy through the files locale; callers own data access, expansion, opening, ancestor reveal, and scrolling.

A `TreeEntry` is `{ path, name, meta?: { kind?, hidden?, size? } }`. Only `/` separates levels; the parent is the prefix before the last `/`, or `root` when there is none. Names remain caller-supplied; repeated paths keep the first entry. Root-key entries are ignored, including the empty root. Missing intermediate directories are added once, with explicit entries taking precedence. An omitted kind means directory when entries lie below that path, otherwise file. Hidden rows use subdued ink without filtering; size is not drawn. Only visible levels sort, directories first and then by natural case-insensitive name order; each level keeps its sorting cache until its names or directory kinds change.

The local `accessory` slot has root scope and owner props `{ entry: TreeEntry }`; its Component may also use the derived `FactoryLocalComponentPropsOf<'sidebar.files.tree', 'accessory'>` seats. It receives only `entry` and the Factory's own seats, not the caller's store or inject face. Supply a module-level Component to preserve its identity. Its content sits beside the main button, never inside its action or disabled scope. The default Component renders nothing. The accessory wrapper always exists in the DOM; CSS hides it without taking row space when the slot is absent or its Component returns empty content.

<a id="the-history-view"></a>
## The history view

The rail's `history` item (a clock glyph) replaces the workbench's columns with `HistoryPanel`; it is offered under the same condition as the git item, and both rest on the one status read. The wide layout is two panes joined by the workbench's divider: the selected commit's page on the leading side and the navigator on the trailing one, with the page's share kept per tab. Below a panel width of 560px — measured on the panel's own box with a `ResizeObserver`, not derived from a window media query — the view is one column: the navigator draws alone, a commit row drills into its page, and a back control returns to the list. A hidden or not-yet-laid-out panel keeps the wide layout, so one window holds both layouts as the reader resizes the Sidebar.

The navigator carries the "History" title, the refs chip, and a reload control above its scroller, so the rows scroll beneath a fixed header. Its first row is the working tree's uncommitted-changes row, shown only while the list starts at `HEAD` — walking all refs or the branch `HEAD` is attached to — and the status read found changes; activating it switches the rail to the git container, which owns those changes. Commit rows follow, each with its commit-graph gutter, the commit's refs as pills (the attached branch first, then local, remote, and tag names; at most two names plus a `+n` pill), the subject, and a second line with the abbreviated hash, the author, and the relative author date whose title states the absolute date. The shown commit's row carries `aria-current`. One page holds `HISTORY_PAGE_SIZE` (50) commits — the same constant the history route serves a request that names no limit; an explicit "Load more" row reads the next page while the ref has commits after the loaded pages, and a reload that fails keeps the drawn rows, states the failure above them, and offers its retry.

The gutter draws the loaded commits' commit graph: `layoutGraph` (`history-graph.ts`) is a pure lane layout, and each row draws the lane segments that cross it and its commit dot, with a ring around the shown commit's dot. Every child keeps its own lane waiting for its parent, so several lanes can wait for one commit, and at that commit's row they meet at its dot: the leftmost waiting lane becomes the dot and the others draw a diagonal from the row's top into it, so a branch's line runs to the dot of the commit it branched from instead of ending between two rows. Each lane keeps its column until the commit it waits for arrives, so a segment away from a dot is vertical and a slanted segment exists only at a branch corner: a fork leaving a dot, or a waiting branch meeting the dot it branched from. A commit's first loaded parent continues the dot's column and hue; each further parent takes the nearest free column beside it, reusing a column an ended branch left, and the fork edge is the diagonal from the dot to that column. Free columns can therefore sit between two open lanes until a later branch takes them. Across rows, the segments compose git's parent edges.

The walked ref's first-parent chain always keeps the leftmost lane, so the mainline reads in one hue through the commits its side branches merge back into. A branch keeps its hue for the life of its lane, and a new branch takes the next hue no open lane uses from a rotating sequence of six — indigo, green, amber, red, violet, teal — so simultaneous lanes never share a hue. At most six lanes are drawn: a lane past the cap clamps into the rightmost drawn column. Rows are 44px tall on a 9px lane pitch, and every row shares the navigator's one gutter width — 16px for one lane up to 61px for six — so no row's text starts at another edge. The gutter is an inline SVG at the row's leading edge, never its own column, and it is not interactive: the row's selection owns the gesture. The list still shows every commit in git's order, and loading another page extends the same graph rather than restarting it: the boundary row is continuous, so a parent outside the loaded page draws no lane until it arrives, and that row gains its outgoing line when it does. Rows already above the boundary can still move when a later page names a parent they could not place, because the lane order depends only on the commits loaded above them.

The refs chip opens a searchable popover listing "All refs" (which walks the repository's `HEAD`) and the refs the refs read returns, grouped into local branches, remotes, and tags; the search filters rows by name and reports when nothing matches. The list walks the branch `HEAD` is attached to by default, and a detached `HEAD` walks all refs. Picking a ref restarts the list at that ref's newest commit and clears the shown page; "All refs" returns to `HEAD`. A picked scope survives a refs read while the repository still reports it — all refs included — and a picked ref that disappears returns the list to the default scope. The filter changes only which history the list walks — it never switches the repository's branch, and the popover states that. A failed refs read is retried from the popover, and the chip names the walked ref so the list's scope is visible above it. Every ref name the view draws — a row pill, the commit page's pill, a filter row and its hover title, the chip — drops the Unicode bidi embedding, override, and isolate controls (`refDisplayName`), because git accepts them inside a ref name and a repository can therefore hold a tag that renders as a different name than the one it is.

The commit page draws the selected commit's message — the body after the subject folds behind a toggle — and a meta line with the abbreviated hash, author, relative date, and up to four ref pills plus `+n`. Its changed-file section states the commit's complete file count, adding the commit's added and deleted totals only when the Host returned every changed file; it then lists each file with git's letter (A, D, M, or R, colored by kind), path, and `+`/`−` counts or a "Binary" label. Folding the section leaves its header drawn and names the file whose comparison is shown, and a note reports how many of how many files the Host's file cap returned. The selected file's comparison is drawn by the shared numbered `DiffHunks` renderer — the same one the working-tree git view and the turn's change review use — and switched between a unified column and side-by-side sides by the shared icon-only `DiffModeControl` toggle beside the shared scope toggle that draws the changed hunks by default, with both choices kept per tab. A created file draws its whole content with a created note, and a binary file, an oversized file, and a file with no lines each have their own filled state. The page is a flex column whose comparison takes the remaining height with its own scroll, so a one-line change fills the column instead of leaving it half empty, and folding the file section gives the comparison more room.

The container seeds its reads on open: the refs first, then the first page of the walked ref. A loaded page selects its first commit, and a loaded commit selects its first changed file — a source file under a `src` directory first, then another code or data file, then the file in the Host's order — so the wide layout opens on content without a gesture. A gesture's read supersedes the one it replaces, and the reload control re-reads the refs, the shown commit, and that commit's selected comparison. While the view is on screen it also refreshes itself: a quiet reread every three seconds of the working tree's status, the refs, and — when the refs moved or the drawn list still states a failure — the walked ref's first page. Every settlement writes only what changed, so an unchanged repository costs no render and the rows never blank out: commits that landed at the tip are prepended above the loaded pages, keeping the pages the reader loaded and the commit page they are reading, while a rewritten ref replaces the list. A read the reader asked for owns its route, so a poll never starts a second read of the same kind; a collapsed Sidebar or a hidden tab stops the reads, and coming back reads at once. A reload still reads only the first page, so rows the reader loaded from later pages drop until they are loaded again. The list keeps its scroll offset across container switches, the commit page keeps its offset for the commit it draws, and walking another ref starts the list at the top.

The four history routes read only: nothing in the view stages, commits, checks out, discards, or rewrites anything, and the dirty-changes row leaves the history view rather than acting on the working tree.

## Known Limitations and Deferred Work

<a id="known-limitations-and-deferred-work"></a>
- **Listing only.** No search, artifact filter, drag-and-drop, or rename in the tree.
- **The git and history views are read-only.** They list the working tree and the repository's commits and draw comparisons; staging, committing, switching or creating branches, discarding, and rewriting history are not built. Picking a ref in the history filter never checks anything out.
- **The history list pages at 50 and a reload reads only the first page.** Rows loaded from later pages drop on a reload; the quiet reread prepends commits that landed at the tip but replaces the list when the walked ref was rewritten.
- **The git summary has no line counts.** The working-tree status route carries paths and kinds, not added and deleted lines, so the changed-path list and its summary report the complete change count and the sync state without per-file totals.
- **A merge commit compares against its first parent.** Its page shows what the merge introduced relative to the commit it merged into; comparing two arbitrary commits is not built.
- **A subdirectory session sees its own subtree.** When the Session's working directory is below the repository root, history lists and compares only paths inside it: a commit that changed only files above the working directory shows an empty changed-file section, and a rename whose origin lies outside drops the origin.
- **The changed-file list is capped by the Host.** A commit with more changed files than the `workspace-changes` `maxFiles` setting shows the first ones, states the complete count, and omits its added/deleted totals; the setting and the complete first-parent and subdirectory rules belong to [that service](../../deliverables/workspace-changes/README.md#use-this-package).
- **The commit graph draws at most six lanes.** A lane past the sixth clamps into the rightmost drawn column, so a history with more open branches than that shows those lanes sharing the last column; the list still shows every commit in git's order.
- **No history search or path filter.** The navigator only walks one ref's commits by paging: there is no commit-message search, path or author filter, or two-commit comparison.
- **Expand All is one generation deep.** It opens every directory the tree has already listed; a directory that first appears in a level opened by that press needs a second press.
- **The dividers are pointer-only.** The files, git, and history splits expose `role="separator"` but no keyboard route to move them.
- **One content column.** The files container keeps one content column; a split editor is not built, and a narrow pick is a preview drill-down rather than a second column.
- **One root.** The tree is rooted at the session's working directory; there is no way to browse above it, and the Host refuses paths outside the workspace root anyway.
