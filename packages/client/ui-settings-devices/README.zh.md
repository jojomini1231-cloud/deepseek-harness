# @deepseek-ai/dsh-client-ui-settings-devices

[English](README.md) | 中文

## 概述

设备管理页列出登录过本部署的浏览器，在操作者为其命名之前，每台设备都根据自身 User-Agent 显示名称，并提供重命名与吊销。它在 Host 提供生成的 `devices` 命名空间时注册进 `settings.section`，因此没有浏览器设备名册的部署完全看不到它。

<a id="use-this-package"></a>
## 使用本包

该分区通过 `settings.section` 注册，并经由 `devices` Remote 命名空间读取名册。被操作者重命名过的设备显示该标签；其余行显示本页根据所存 User-Agent 解析出的浏览器与系统（由本包自己的字典措辞），并在旁边显示用于识别未命名浏览器的原始 agent 字符串。首次访问与最近活跃时间使用共享的相对时间分桶，因此两个界面为同一时刻给出相同说法。

吊销会先确认，并直白说明后果，因为设备 id 随页面读不到的 cookie 传递：无法告诉操作者哪一行是他们自己正在使用的浏览器，所以吊销它会立刻把他们退出登录。相关控件带有错误色；每一行自己的按钮都会点名它所作用的设备。在确认被接受之前不会发生任何吊销；Host 的拒绝会显示在页面上，而不是无声失败，而一次被接受的写操作会清掉上一次的拒绝提示，而不是让它继续挂着。

页面在打开时读取一次、在每次被确认的写操作后再读取一次，然后显示 Host 报告的结果；各行以该结果为准，而不是对写操作改变了什么做本地猜测。吊销了自己那台设备的浏览器无法再读取名册，因此页面会如实说明这一结果，并且不提供无法成功的重试。相对时间会按定时器重新采样，首次读取时显示占位行而不是空名册。

## 模型体验

无。设备名册承载的是 HTTP 认证事实，从不进入模型提示词、Session 日志或工具结果。

#### KV Cache 影响

模型请求前缀没有任何变化。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

- **页面无法标出正在阅读它的这个浏览器。** 设备 id 随签名 cookie 传递，同源上任何脚本都读不到它——这正是该身份不可伪造的原因——因此没有客户端手段识别当前行。要做到这一点，需要把该事实从准入一路传到 RPC 处理器，那属于 Connection 与 Gateway 层。
- **两个同时打开的设置面板不会自行一致。** 名册在打开时与每次写操作后读取，没有 Host 事件把变化推送给其他客户端；增加该事件需要在 API Remotes 转发事件允许列表中加一条 `devices/changed`。
- **已打开的流会比吊销存活更久。** Host 会在该设备的下一次请求（包括 WebSocket 升级）上拒绝它，但已经打开的流会持续运行到该传输重连或页面刷新为止。
