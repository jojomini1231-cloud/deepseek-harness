# DeepSeek Harness

English | [中文](README.zh.md)

DeepSeek Harness (`dsh`) is an open-source agent harness developed by [DeepSeek AI](https://deepseek.com).

It is built on an **everything-is-a-plugin** architecture and powered by [Cordis](https://github.com/cordiverse/cordis), whose design is described in [_A Programming Paradigm for Spatiotemporal Composability_](https://arxiv.org/abs/2608.25512).

Documentation: [https://deepseek-harness.github.io/deepseek-harness/](https://deepseek-harness.github.io/deepseek-harness/)

## Developer preview

## Run

### Run from `npm`

Install `Node.js`, then run:

```sh
npx @deepseek-ai/dsh web
```

The command starts the Web UI at `http://127.0.0.1:3080` by default and opens it in the default browser for a local launch. An SSH launch only prints the host URL because the SSH client or editor owns the local forwarded address. Pass `--no-open` to run the server without opening a browser. See [Web UI guide](docs/user/guide/index.md).

### Run from source

To run from a repository checkout:

```sh
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web
```

`pnpm run build` prepares the repository artifacts. `pnpm dsh web` uses those built artifacts without rebuilding.

### Run the Desktop app

The Electron desktop shell wraps the same bundled runtime in a native window. From a repository checkout, launch the development shell after `pnpm install`:

```sh
pnpm run dev:desktop
```

The command prepares the bundled interpreter payload on first use (which may download locked dependencies) and launches with an isolated development home; see the [Desktop README](apps/desktop/README.md) for the development flow. On a Linux x64 host you can also build a local unsigned AppImage that runs the same application without a checkout:

```sh
pnpm run package:desktop:linux:x64:unsigned
```

The AppImage requires FUSE at run time and needs no `.env` file or signing configuration. The application runs its Host on the bundled Node instead of Electron, because Electron's Linux binaries conflict with the bundled libvips bindings ([electron#46323](https://github.com/electron/electron/issues/46323)); the [Desktop README](apps/desktop/README.md) documents this and the remaining Linux limitations.
